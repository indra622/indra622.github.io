용어 정리

한 번 요청 vs 계속 도는 루프

도구 호출은 모델이 한 턴 안에서 하는 일. 루프는 그 바깥에서 턴을 다시 시작하는 장치이고, 기억은 파일과 git에 남김.

구현 방식

Ralph를 구현하는 두 가지 방식

snarktank/ralph: 매번 새 프로세스
  • ralph.sh가 반복마다 Claude Code나 Amp를 새로 실행
  • 기억은 git, prd.json, progress.txt
  • 기본 반복 상한 10회. 모든 항목이 passes: true면 끝
  • /ralph 스킬은 PRD를 prd.json으로 바꿀 뿐, 반복 실행은 셸 스크립트가 함
Anthropic 공식 ralph-loop 플러그인: 같은 세션
  • 현재 세션 안에서 Stop hook이 종료를 막고 같은 프롬프트를 다시 넣음
  • --max-iterations: 기본값 무제한, 꼭 설정하라고 권장
  • --completion-promise: 정확히 같은 문자열일 때만 멈춤

원형은 Geoffrey Huntley의 2025-07-14 글. while :; do cat PROMPT.md | claude-code ; done 한 줄짜리 셸 루프였음. 특정 회사의 발명이나 하나의 플러그인을 가리키는 말이 아님.

기대 결과

  • 식비 20000, 교통 3000
  • 데이터 4행은 카테고리가 없으므로 무효로 표시
  • 무효 행은 합계에서 제외

실패와 종료

  • 합계가 다르거나 4행이 합계에 들어가면 실패
  • 테스트 3개 통과와 화면 확인 후 완료 보고

실제 카드 내역이나 개인정보는 쓰지 않음. AI에게는 이 표와 기대 결과를 그대로 넘김.

데모 SIMULATION / 미리 정한 결과를 재생, AI나 셸을 실행하지 않음

루프 한 바퀴 보기

단계별 결과 (인쇄용 요약)

  • 1 요청과 명세: 7번 슬라이드의 표와 기대 결과
  • 2 구현 v1: 카테고리별 합계
  • 3 테스트 실패: 빈 카테고리 5000이 합계에 포함, 4행 무효 표시 없음
  • 4 수정: 빈 카테고리 행을 건너뛰고 무효 목록에 추가
  • 5 테스트 통과 3/3
  • 6 완료 기준 확인: 합계, 무효 표시, 가짜 데이터, 화면 표시
  • 7 멈춤: 완료 보고
멈춤 조건

루프는 잘 멈추는 것까지가 설계

완료

기준을 모두 확인함

테스트 통과 + 명세의 나머지 조건 확인 후 보고

막힘

같은 오류가 반복됨

예: 같은 오류 3번이면 멈추고 사람에게 넘김. 무한 재시도 금지

예산 상한

정한 한도에 도달

반복 횟수나 비용 한도에 닿으면 멈춤

--max-iterations는 반복 횟수 상한일 뿐. 비용 한도나 계정 설정을 대신하지 않음.

completion promise는 모델이 출력한 문자열. 독립 검증이 아니므로 결과는 사람이 다시 확인.
